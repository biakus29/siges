L'APPLICATION
-------------
  Interface complète (React compilée, incluse) + API PHP avec stockage
  MySQL EXCLUSIF. Compatible PHP 7.0 et plus (PHP 7 et PHP 8). Aucune dépendance
  à installer : pas de Node.js, pas de Composer — uniquement PHP.

  Fonctions : inscriptions et dossiers élèves (import CSV), encaissements
  et reçus, bourses, solvabilité, journal de caisse, notes et bulletins
  (QR de sécurité), discipline et absences en heures, documents scolaires,
  statistiques, rapports imprimables (en-têtes gris neutres),
  personnalisation, multi-établissements, exports CSV, envois WhatsApp.

  NOUVEAUTÉS v7.2 — ENREGISTREMENT PARFAITEMENT TRANSMIS (TRANSPORT
  AUREL1) :
  • certains pare-feu applicatifs d'hébergement (WAF/ModSecurity)
    refusent les GROS POST JSON — HTTP 406 — alors que tout le reste
    fonctionne (connexion, lecture) : l'application affichait alors
    « Hors ligne » et les saisies ne rejoignaient jamais MySQL ;
  • la base est désormais envoyée ENCODÉE en base64 (corps
    « AUREL1:<base64> », Content-Type text/plain) : le pare-feu ne peut
    plus l'inspecter ni la refuser ; le serveur la décode et l'enregistre
    normalement dans MySQL — VÉRIFIÉ sur l'hébergement concerné ;
  • l'ancien format JSON reste accepté (compatibilité pendant la mise à
    jour des postes) ; aucune configuration à changer.

  NOUVEAUTÉS v7.1 — DIAGNOSTIC DE CONNEXION INTÉGRÉ :
  • le badge de synchronisation (✓ Base à jour / ⟳ Enregistrement… /
    ⚠ Hors ligne — file d'attente) est désormais CLIQUABLE : il ouvre la
    fenêtre « Diagnostic de connexion » qui rejoue depuis le navigateur
    les appels exacts de l'application (fonction réseau fetch native ou
    remplacée par une extension, sonde api/health, lecture et envoi
    authentifiés vers MySQL) et affiche pour chacun le statut HTTP, la
    latence et un verdict — plus la liste des dernières erreurs d'envoi
    avec leur heure ;
  • « Réessayer l'envoi maintenant » force un nouvel envoi immédiat des
    modifications en attente ;
  • RAPPEL : les données sont écrites directement dans MySQL à CHAQUE
    enregistrement — la « file d'attente » n'est qu'un filet de sécurité
    qui conserve les modifications sur le poste si le serveur devient
    injoignable, puis les envoie automatiquement.

  NOUVEAUTÉS v7.0 — FONCTIONNEMENT EN LIGNE SUR INTERNET (FLOTTE) :
  • CORRECTION DÉFINITIVE du message « Serveur injoignable » sur les
    hébergements internet : de nombreux hébergeurs (PHP en CGI/FastCGI)
    ne transmettent pas l'en-tête Authorization à PHP — la connexion
    réussissait puis CHAQUE enregistrement était refusé. Le jeton de
    session est désormais aussi envoyé dans l'en-tête X-Aurel-Token
    (toujours transmis) et le serveur accepte l'un ou l'autre.
  • SESSIONS À RENOUVELLEMENT GLISSANT : le jeton est réémis
    automatiquement pendant le travail — plus de session qui expire
    en pleine journée.
  • UTILISATION SIMULTANÉE PAR PLUSIEURS OPÉRATEURS : quand deux
    opérateurs enregistrent en même temps, la base locale est FUSIONNÉE
    avec la base du serveur (fusion à trois voies, document par
    document) : le travail de chacun est conservé, plus aucune perte.
  • INDICATEUR DE SYNCHRONISATION permanent dans la barre supérieure :
    « Base à jour » / « Enregistrement… » / « Hors ligne — file
    d'attente » (nouvel essai automatique toutes les 8 s).
  • GARDE ANTI-PERTE à la déconnexion : si des modifications n'ont pas
    été confirmées par le serveur, une confirmation explicite est
    demandée avant de perdre quoi que ce soit.
  • RAPPEL DE L'ARCHITECTURE : toutes les données vivent
    EXCLUSIVEMENT dans la base MySQL (phpMyAdmin) — paramètres saisis
    et testés à l'installation ; multi-établissements ; chaque
    enseignant se connecte avec ses identifiants pour saisir les notes
    des classes qui lui sont attribuées ; seul le superadministrateur
    visualise le journal global des actions.

  NOUVEAUTÉS v6.9 — CORRECTION « SERVEUR INJOIGNABLE » À L'INSTALLATION :
  • CAUSE : sur un serveur distant (hébergement, MySQL distant), le
    premier appel au serveur peut être lent (PHP à froid + connexion
    MySQL distante). Si la connexion était cliquée avant la fin de la
    détection du serveur (2,5 s), l'application basculait par erreur en
    mode LOCAL de secours — le jeu de démonstration local acceptant les
    mêmes identifiants (admin/admin2026), la session semblait normale…
    mais toutes les saisies restaient dans le NAVIGATEUR : après
    déconnexion/reconnexion, la base du serveur (vide) réapparaissait.
  • CORRECTIONS : la connexion ATTEND la détection du serveur ; la sonde
    passe à 8 s et est RETENTÉE à chaque tentative de connexion ; le
    repli local est signalé par un AVERTISSEMENT sur l'écran de
    connexion ; une base locale de secours n'est jamais envoyée au
    serveur ; les refus du serveur affichent leur VRAI motif (session
    expirée, erreur explicite) au lieu de « Serveur injoignable ».

MÉTHODE 1 — XAMPP / WAMP / LARAGON (recommandée)
------------------------------------------------
  1. Installez XAMPP (https://www.apachefriends.org) et démarrez Apache.
  2. Copiez ce dossier dans le dossier des sites :
        C:\xampp\htdocs\aurel-school-siges\     (XAMPP)
        C:\wamp64\www\aurel-school-siges\       (WAMP)
  3. Ouvrez  http://localhost/aurel-school-siges/install.php
  4. L'assistant vérifie l'environnement, vous laisse choisir
     l'ADRESSE du serveur (localhost, IP locale, port…) puis la base :
       • Base vide prête pour la production — NOM DE VOTRE ÉTABLISSEMENT
         et unique compte administrateur créés ici (plus aucune donnée
         de démonstration depuis la v6.7)
       • ou reprise d'une base existante (mise à jour sans perte)
  5. Serveur MySQL local (XAMPP) ou DISTANT avec phpMyAdmin : indiquez
     l'hôte fourni par votre hébergeur (ex : sql.votredomaine.com) —
     « localhost » si MySQL est sur la même machine que l'application.
  6. Cliquez « Ouvrir l'application » — c'est installé.

STOCKAGE : MYSQL EXCLUSIF (aurel_school)
------------------------------------
  Les données vivent dans votre serveur MySQL/MariaDB (XAMPP le fournit) :
  • à l'installation : hôte (127.0.0.1 en local, ou l'adresse du serveur
    DISTANT fournie par votre hébergeur — ex : sql.votredomaine.com),
    port (3306), utilisateur, mot de passe et NOM DE LA BASE
    (aurel_school par défaut) — création automatique de la base si
    l'utilisateur a le droit CREATE (sinon créez-la depuis phpMyAdmin) ;
  • accessible ensuite depuis phpMyAdmin ou tout client MySQL
    (tables : entities — données en JSON par collection — et meta) ;
  • sauvegarde : mysqldump -u utilisateur -p aurel_school > sauvegarde.sql
    (ou l'export phpMyAdmin), et bouton « Exporter la base (ZIP) ».

DÉMARRAGE AUTOMATIQUE AVEC L'ORDINATEUR
----------------------------------------
  Windows (mode PHP intégré) :
    1. Double-cliquez sur INSTALLER-DEMARRAGE-AUTO.bat
    2. L'application démarre avec Windows (fenêtre réduite)
    3. Port : créez un fichier port.txt (ex : 8080) — défaut 4000
       Navigateur ouvert au démarrage : fichier vide OUVRIR-NAVIGATEUR.txt
    4. Retrait : RETIRER-DEMARRAGE-AUTO.bat
  Windows (mode XAMPP/WAMP) : installez Apache et MySQL comme SERVICES
    depuis le panneau XAMPP (icône en forme de croix rouge → cocher).
  Linux/macOS : bash installer-demarrage-auto.sh [port]
    (service systemd utilisateur + repli ~/.profile ; retrait :
     bash retirer-demarrage-auto.sh)

MÉTHODE 2 — PHP SEUL (sans Apache)
----------------------------------
  Windows : double-cliquez sur  DEMARRER-WINDOWS.bat
            (il détecte PHP/XAMPP, vous demande le PORT — défaut 4000 —
             démarre le serveur et ouvre le navigateur ; ouvrez
             install.php au premier lancement)
  Linux/Mac : bash DEMARRER-LINUX-MAC.sh [port]

MÉTHODE 3 — HÉBERGEMENT MUTUALISÉ
---------------------------------
  1. Envoyez le contenu de ce dossier par FTP dans votre espace web.
  2. Ouvrez  https://votre-domaine/install.php  et suivez l'assistant.
  3. IMPÉRATIF après l'installation : supprimez install.php du serveur.
  • Le dossier data/ est protégé par .htaccess (Apache) ; sur autre
    chose qu'Apache, vérifiez que https://votre-domaine/data/ renvoie
    « Accès interdit » (ce dossier ne contient plus la base depuis le
    stockage MySQL — uniquement le journal des tentatives de connexion).
  • Nécessite AllowOverride All (défaut chez la plupart des hébergeurs).

PREMIÈRE CONNEXION (installation de production)
------------------------------------------------
  L'installation crée un UNIQUE compte : l'administrateur dont vous avez
  choisi l'identifiant et le mot de passe (aucun compte de démonstration
  n'est créé — le mode démonstration a été retiré en v6.7).
  • Connectez-vous avec cet identifiant, puis créez les autres comptes
    (économe, censeur, enseignants…) dans Administration → Utilisateurs
    & profils.
  • RÉSEAU D'ÉTABLISSEMENTS : le superadministrateur (console réseau)
    se crée à l'installation (case « Réseau d'établissements ») ou, sur
    une installation existante, depuis Utilisateurs & profils tant
    qu'aucun n'existe (voir NOUVEAUTÉS v6.8).
  • Une ancienne installation « démonstration » (versions ≤ 6.6) conserve
    ses comptes de démonstration (admin/admin2026, econome/econome2026…,
    liste complète : manuel docs/, annexe A) : changez ces mots de passe
    ou réinstallez une base de production.

  • Bouton « Exporter la base (ZIP) » : archive complète (élèves,

SÉCURITÉ
--------
  • Session verrouillée automatiquement après 5 minutes d'inactivité.
  • Droits par utilisateur définis par l'administrateur (matrice
    hérité/aucun/lecture/écriture par module).
  • Limitation des tentatives de connexion (5 échecs → 30 s).
  • data/, config.php, seed/ jamais servis par le serveur.

DÉPANNAGE
---------
  • Page blanche / routes ne marchent pas  → AllowOverride All requis
    (Apache) ; ou utilisez DEMARRER (php -S).
  • « Extension PDO MySQL : absente »    → activez pdo_mysql dans
    php.ini (XAMPP : déjà incluse — ne la désactivez pas).
  • Erreur à l'import de photos     → augmentez post_max_size /
    upload_max_filesize (24M recommandé ; les lanceurs le font).
  • Port occupé (php -S)             → choisissez un autre port au
    lancement (DEMARRER-WINDOWS.bat le demande).
